## 缓存系统修复

### 问题分析
- Redis 容器健康运行，但 `keyspace_hits/misses` 均为 0，说明缓存层未生效
- `_down` 旗标为永久性自杀开关：一旦连接失败，进程生命周期内永不重试
- BM25 用文件缓存存储索引而非查询结果，属于合理设计
- `__init__` 中存在 `self._client = None` 重复赋值

### 修复内容
1. **Circuit Breaker 三态机制**：将 `_down: bool` 替换为 `_down_since: float` 时间戳
   - **Closed**：`_down_since is None`，操作正常
   - **Open**：失败后 30 秒内跳过所有 Redis 调用
   - **Half-Open**：30 秒后自动尝试重连，成功则 Closed，失败则 Open
2. **存量连接保活检测**：每次 `_ensure_client` 对已有 client 执行 `ping()`，发现失效则重建
3. **添加 Prometheus 指标**：`rag_cache_hits_total` / `rag_cache_misses_total` / `rag_cache_failures_total`
4. **清理重复赋值**：第 40-41 行 `self._client = None` 重复已移除

### 测试
- `tests/unit/test_cache.py` 37 例全数通过

### 增强（甲）
1. **TTL 抖动**：`set()` 写入时施加 ±10% 随机 jitter，防缓存雪崩
2. **结构化事件日志**：熔断器状态变更（Closed↔Open↔Half-Open）通过 `logger.bind(event="cache_circuit_state")` 发射结构化日志
3. **`reconnect_now()`**：新增主动重连方法，可绕过冷却期立即重试
4. **存量连接保活**：已有 client 每次调用前 `ping()` 验证，失效自动重建
